# Partner POV Dojo — 시나리오 기반 워크숍 기획안

파트너 SA/SE가 고객 POV를 직접 계획하고, 기술 근거를 검증하고, 고객에게 결과와 다음 단계를 설명하도록 훈련하는 4시간 워크숍 운영 기획서입니다. Wiz PSA와 코치는 진행자·고객 역할자·평가자로 참여합니다.

## 대표 고객 시나리오

가상 APJ B2B SaaS 기업 ‘하늘커머스’가 6주 뒤 서비스 확대를 앞두고, 주문 API와 고객 데이터 접근 위험의 우선순위를 검증합니다. AWS 운영·비운영 2개 계정과 서울·싱가포르 리전의 핵심 자산 표본 8개를 대상으로, 10영업일 POV를 4시간 모의 실습으로 압축합니다.

- 위험 A: 외부 운영 API의 취약점, 연결된 IAM 역할과 고객 데이터 읽기 권한이 결합된 위험을 검증합니다.
- 위험 B: 취약점 심각도가 높은 내부 개발 배치 서버를 같은 기준으로 비교합니다. 외부 노출과 중요 데이터 접근이 확인되지 않은 경우에도 후속 조치는 관리합니다.
- 학습 목표: 취약점 점수만이 아니라 노출·권한·데이터·업무 중요도의 증거를 연결해 조치 순서와 사업 영향을 설명합니다.

이는 교육용 가상 사례입니다. 실제 침해·유출이 발생했다는 뜻이 아니며, 실제 테넌트에서 해당 위험을 확인했다는 주장도 아닙니다.

## 성공기준과 평가

- S1 가시성: 합의한 핵심 자산 8개를 실제 ID와 대조합니다. 전체 계정 자산의 완전성을 의미하지 않습니다.
- S2 우선순위: 위험 A·B의 근거와 제약을 설명하고 고객이 조치 순서를 수용합니다.
- S3 실행 가능성: 담당자·기한·변경 영향·재검증 기준이 있는 조치 계획을 합의합니다. 계획 합의와 실제 조치 효과 검증은 별도로 기록합니다.

워크숍 평가 제안은 팀 60점과 개인 40점으로 구성됩니다. 총점 80점 이상, 개인 30점 이상, 개인 증거 항목 10점 충족을 함께 확인합니다. 정확한 항목과 관찰 방식은 DOCX 평가표를 따릅니다.

워크숍 통과는 실제 고객 POV 독립 수행의 최종 인증과 다릅니다. 참고 육성 모델의 필수 교육, Wiz 주도 POV 2회 섀도잉, 파트너 주도 수행 관찰 및 최종 승인 절차와 연결하되, 실제 적용 기준은 프로그램 오너와 확정해야 합니다.

## 운영 전 준비와 사용 순서

1. D-7: 고객 설정과 성공기준을 확정하고 가상 자산 별칭을 실제 테넌트 자산·Issue ID·계정·리전·증거에 매핑합니다.
2. D-3: 참가자 로그인·조회 권한·수집 상태를 확인하고, 참가자 워크북과 강사용 답안·상황 카드를 분리합니다.
3. D-1: 참가자 권한으로 4시간 흐름을 리허설하고 두 평가자의 채점 기준을 맞춥니다.
4. 당일: 파트너가 직접 수행하도록 역할을 교대하고 개인별 콘솔 수행과 설명 근거를 관찰합니다.
5. 종료 후: 개인 보완점을 정리하고 실제 고객 POV 섀도잉·관찰 평가로 연결합니다.

기본 돌발 상황은 ‘핵심 자산 8개 중 6개만 보임’과 ‘운영 API를 중단할 수 없음’입니다. 문서의 추가 카드들은 기본 카드의 대체 확장안이며 모두 당일 일정에 더하는 것이 아닙니다.

## 적용 시 주의사항

- 테넌트가 존재하는 것과 실습 데이터가 준비된 것은 다릅니다. 실제 CVE 적용 여부, 네트워크 경로, IAM 유효 권한 및 데이터 분류 근거를 별도로 확인해야 합니다.
- 증거가 부족하면 일부 충족 또는 미검증으로 기록합니다. 사전 캡처 분석을 실제 테넌트 검증 완료로 표시하지 않습니다.
- 공유 테넌트는 조회 중심으로 운영하고, 승인 없이 운영 환경을 변경하거나 공격·정보 유출을 재현하지 않습니다.
- 교육용 전후 자료와 실제 고객 환경의 조치 효과를 구분합니다. 측정하지 않은 조사 시간 절감·비용 절감·매출 효과를 주장하지 않습니다.
- 이 폴더는 기획서와 설명 문서를 제공합니다. 별도의 참가자용 워크북, 실습 인프라 배포 코드, 최신화된 PPT는 포함하지 않습니다.
